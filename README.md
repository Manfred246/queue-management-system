# Система управления очередью

Консольное приложение для организации обслуживания посетителей.
Посетитель выбирает услугу и получает талон. Сотрудник вызывает следующего
посетителя и завершает обслуживание.

## Целевая аудитория

- посетители организаций с электронной очередью;
- сотрудники, обслуживающие посетителей;
- администраторы, управляющие услугами и очередями.

## Возможности

- просмотр, поиск, отбор и сортировка услуг;
- добавление услуги и связанной с ней очереди;
- добавление и просмотр пользователей;
- открытие и закрытие очереди, изменение доступности услуги;
- выдача талона с номером, временем выдачи и оценкой ожидания;
- вызов следующего посетителя, отмена талона и завершение обслуживания;
- просмотр истории талонов;
- сохранение данных в JSON и восстановление при запуске.

## Основные сущности

| Класс | Основные атрибуты | Основные методы |
| --- | --- | --- |
| `User` | id, name, role | `can_receive_ticket`, `__str__` |
| `Service` | id, name, average_service_time, is_available | `set_available`, `__str__` |
| `Queue` | id, name, service, prefix, is_open, last_ticket_number | `set_open`, `can_issue_ticket`, `active_tickets`, `call_next`, `__str__` |
| `Ticket` | id, number, user, service, queue, status, issued_at | `cancel`, `call`, `complete`, `position`, `wait_time`, `status_text`, `__str__` |

У каждого класса есть конструктор `__init__`. Очередь хранит ссылку на услугу,
а талон связывает пользователя, услугу и очередь. Коллекции содержат объекты
этих классов. При загрузке JSON ссылки восстанавливаются по ID.

Статус талона, открытость очереди, счётчик номеров и доступность услуги
читаются через свойства `@property`, а изменяются методами с проверками.
Метод `__str__` задаёт представление каждого объекта для вывода.
Наследование для текущих сущностей не требуется.

## Правила работы

Одна очередь обслуживает одну услугу. Посетители вызываются по возрастанию
номеров талонов. В очереди может быть только один вызванный посетитель.
У посетителя может быть один активный талон в каждой очереди.
Сотрудникам талоны не выдаются. Роли хранятся как данные; входа в систему пока нет.

Статусы талона: `waiting`, `called`, `completed`, `cancelled`.
Отменить можно ожидающий или вызванный талон, завершить — только вызванный.
Отменённые талоны остаются в истории, их номера не используются повторно.

Закрытие очереди или отключение услуги запрещает выдачу новых талонов.
Обслуживание уже выданных талонов продолжается.
Оценка ожидания — число активных талонов впереди, умноженное на среднее время
услуги. Для вызванного посетителя учитывается полное среднее время обслуживания.

## Структура проекта

- `main.py` — меню и вывод данных;
- `users.py` — класс пользователя и добавление пользователей;
- `services.py` — класс услуги, добавление, поиск, отбор и сортировка;
- `queues.py` — класс очереди и добавление очередей;
- `tickets.py` — класс талона, выдача и поиск талонов;
- `storage.py` — загрузка и сохранение JSON;
- `validation.py` — проверка данных и связей в JSON;
- `utils.py` — проверка значений и консольный ввод;
- `data/state.json` — данные приложения;
- `tests/` — автоматизированные тесты;
- `requirements.txt`, `pytest.ini`, `.flake8` — зависимости и настройки проверок.

## Запуск и проверки

Требуется Python 3.10 или новее. Приложение использует стандартную библиотеку.
`pytest` и `flake8` нужны для проверки проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

В Windows используйте `python -m venv .venv` и активируйте окружение командой
`.venv\Scripts\Activate.ps1` в PowerShell.

Проверки из корня проекта:

```bash
python -m pytest -v
python -m flake8 .
```

Тесты проверяют методы классов, поиск и отбор услуг, порядок вызова,
переходы статусов, загрузку и сохранение JSON, обработку ошибок и меню.

## Хранение данных

JSON содержит четыре списка: `users`, `services`, `queues`, `tickets`.
Связи записаны в полях `user_id`, `service_id`, `queue_id`, а время выдачи —
в строке `issued_at` в формате ISO 8601. После загрузки создаются объекты классов.
Формат данных ПР2 сохранён.

Данные сохраняются после каждого успешного изменения. Перед изменением меню
создаёт копию состояния. Если операция или запись не удалась, рабочие данные
остаются прежними. Файл сначала записывается с расширением `.tmp`, затем
заменяет основной файл.

Если файла нет, используются начальные данные. Если JSON повреждён,
программа сообщает об ошибке и завершает запуск, сохраняя файл для исправления.
Путь к данным определяется относительно проекта. Одновременно следует
запускать только один экземпляр программы.

## Развитие по практическим работам

- ПР1: получение талона, проверка выдачи, формирование номера и расчёт ожидания.
- ПР2: коллекции, функции, модули, меню, JSON и тесты.
- ПР3: классы `User`, `Service`, `Queue`, `Ticket` и коллекции объектов.

Функции ПР1 сохранены и используются методами классов:
`can_issue_ticket`, `create_ticket_number` — в `queues.py`;
`calculate_wait_time`, `get_ticket_status` — в `tickets.py`.
Поиск, добавление в коллекции и работа с файлами остались обычными функциями.
Изменение состояния отдельных объектов выполняется их методами.
Версии ПР1 и ПР2 доступны в истории Git.
