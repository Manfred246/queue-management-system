# Система управления очередью

Консольное приложение для управления потоком посетителей организации.
Посетитель выбирает услугу и получает талон, а сотрудник вызывает посетителей
в порядке очереди и завершает обслуживание.

## Целевая аудитория

- посетители организаций, использующих электронную очередь;
- сотрудники, обслуживающие посетителей;
- администраторы, управляющие услугами и очередями.

## Предметная область и сущности

Талон связывает пользователя с услугой и конкретной очередью. Система хранит
состояние очередей, порядок вызова, услуги, пользователей и историю талонов.

| Сущность | Данные | Назначение |
| --- | --- | --- |
| Пользователь | ID, имя, роль | Посетитель (`visitor`) или сотрудник (`employee`) |
| Услуга | ID, название, среднее время, доступность | Вид обслуживания |
| Очередь | ID, название, услуга, префикс, открытость, счётчик | Порядок обслуживания одной услуги |
| Талон | ID, номер, пользователь, услуга, очередь, статус, время | Постановка посетителя в очередь |

Роли пока являются сведениями о пользователях. Аутентификация и разграничение
прав запланированы для веб-версии.

## Возможности ПР2

- просмотр, поиск без учёта регистра, отбор и сортировка услуг;
- добавление услуги вместе с очередью, изменение доступности услуги;
- просмотр пользователей и добавление посетителей/сотрудников;
- открытие и закрытие выдачи талонов;
- получение талона с автоматическим номером и оценкой ожидания;
- просмотр истории, отмена, вызов следующего талона и завершение обслуживания;
- загрузка и сохранение данных в JSON, проверка целостности связей;
- обработка неверного ввода, неизвестных ID и ошибок файлов.

Очередь обслуживает одну услугу. Талоны вызываются по возрастанию номера
(FIFO). В каждой очереди одновременно может быть вызван один талон.
Закрытие очереди и отключение услуги запрещают выдачу новых талонов,
но позволяют обслужить уже выданные. У посетителя может быть только один
активный талон в каждой очереди. Сотрудникам талоны не выдаются.

Статусы: `waiting` (ожидает), `called` (вызван), `completed` (обслужен),
`cancelled` (отменён). Отмена сохраняет историю; номера не используются повторно.
Завершить можно только вызванный талон, отменить — ожидающий или вызванный.

Ожидание равно количеству активных талонов впереди, умноженному на среднее
время услуги. Это приблизительная оценка: для уже вызванного посетителя
учитывается полное среднее время. При отсутствии талонов впереди выводится
«Вы следующий»; «Вас вызывают к окну» появляется после фактического вызова.

## Преемственность ПР1 и ПР2

Сценарий ПР1 сохранён: выбор услуги, проверка выдачи, формирование номера,
расчёт ожидания и вывод талона с временем выдачи.
Функции `can_issue_ticket`, `create_ticket_number`, `calculate_wait_time`
и `get_ticket_status` перенесены из `main.py` в `tickets.py` и доработаны.
Вместо ручного ввода числа посетителей используется фактическая очередь.

Переменные ПР1 преобразованы в коллекции: две услуги и две отдельные очереди.
Основная очередь сохраняет префикс A и начальный счётчик 24 (первый талон A25),
очередь документов использует B (первый талон B1). В ПР2 используются словари
с целочисленными ID и список словарей талонов; пользовательские классы
появятся в ПР3.

## Структура проекта

```text
main.py                 # меню, вывод, управление сценарием
services.py             # функции работы с услугами
users.py                # функции работы с пользователями
queues.py               # функции работы с очередями
tickets.py              # выдача и жизненный цикл талонов, функции ПР1
storage.py              # загрузка и атомарная запись JSON

utils.py                # безопасный ввод и проверки значений

tests/                  # pytest: предметная логика, JSON и меню
requirements.txt        # инструменты разработки
pytest.ini              # настройки тестов
.flake8                 # настройки линтера
```

## Установка и запуск

Требуется Python 3.10 или новее. Само приложение использует только стандартную
библиотеку; pytest и flake8 нужны для проверки проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Проверки из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m flake8 .
```

В активированном окружении можно использовать `python main.py`, `pytest -v`
и `flake8 .`. При успешной проверке flake8 ничего не выводит.

## Формат и сохранение данных

`data/state.json` содержит объект с четырьмя списками: `users`, `services`,
`queues`, `tickets`. Связи хранятся через `user_id`, `service_id`, `queue_id`;
время `issued_at` — строка ISO 8601. Например, запись талона:

```json
{
  "id": 1,
  "number": 25,
  "user_id": 1,
  "service_id": 1,
  "queue_id": 1,
  "status": "waiting",
  "issued_at": "2026-10-07T12:00:00"
}
```

После успешного изменения сохраняются все коллекции вместе. Запись идёт
во временный файл, затем он заменяет основной: ошибка записи не повреждает
старое состояние. Меню применяет изменения к копии и принимает её только
после успешного сохранения. При повреждённом JSON программа сообщает об
ошибке и завершает запуск, сохраняя файл для исправления. При отсутствии файла
используются стартовые услуги и очереди; первый успешный запрос на изменение
создаёт файл. Путь определяется относительно `storage.py`, а не текущего каталога.

Это локальное однопользовательское приложение. Одновременная запись из
нескольких процессов пока не поддерживается.

## Проверка требований и план развития

ПР2 реализует коллекции, циклы, функции с аннотациями и документированием,
модули, исключения, файлы и контекстные менеджеры. Отбор использует списковые
включения, сортировка — `lambda`, обработка активных талонов — генератор.
Тесты проверяют поиск/отбор, выдачу, FIFO, запреты переходов статусов,
независимость очередей, восстановление JSON, ошибки записи и пункты меню.

Для ПР3 планируются классы `User`, `Service`, `Queue`, `Ticket`: талон будет
ссылаться на объекты пользователя, услуги и очереди. Поиск, обработка коллекций,
консольный ввод и хранение останутся функциями соответствующих модулей.

Дальнейшие этапы: Django, база данных, регистрация и аутентификация,
разграничение прав, CRUD, REST API, Docker и CI/CD.
